# C1 retry feedback, played in the real game

The [held-GO clip](held-go.mp4) is a silent 852×392 production-game capture of the pallet-ramp failure and checkpoint respawn. The [causeway clip](causeway-loop.mp4) drives the existing clean reference to Marker 3, then holds GO and lean back until the bike loops on the pallet steps. Both are played recordings through the actual HUD, not posed UI frames. [Capture metadata](held-go-capture.json) and [causeway metadata](causeway-capture.json) record 97 and 51 rendered frames respectively.

The HUD now replaces the one-size-fits-all **BAIL +1** explanation with a short, location-specific retry cue while leaving that kinetic banner intact. At the deck crash it says **DECK LANDING / BRAKE BEFORE RAMP · RELEASE GO AT LIP**. The measured causeway loop says **LOOPED ON THE STEPS / RELEASE LEAN BACK · RIDE LEVEL**. A nose-down causeway fault gets different advice. The correction remains for 3.2 simulated seconds, through the automatic one-second checkpoint respawn, then the ordinary approach cue returns. It is only used for C1 faults in those authored windows; manual restarts do not produce it.

[Timing and replay data](replay.json) show held GO faulting at tick 2128, x=234.414 m, and automatically respawning at tick 2248, x=180.692 m: exactly 120 ticks (1.0 s). A manual restart on the first post-fault tick immediately returns to `riding` at the same checkpoint ([one-tick report](timing.json)). The causeway loop faults at tick 2791, x=314.676 m, and auto-respawns at tick 2911. Both recordings have byte-identical final state hashes in Node and in two fresh headless browser loads. This UI patch does not alter the simulation.

`pnpm typecheck`, `pnpm lint` and the three focused DOM tests passed. These clips verify presentation and scripted input only. Fresh phone-touch players still need to show that they read the correction, change input, clear C1 in a measured number of attempts, and find manual restart without prompting. Physical-device restart latency is still unmeasured.
