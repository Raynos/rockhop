# C-island production-style review build

The selected C-island scene now has an explicit **review-build-only** switch: `VITE_MAP_3D_REVIEW=1 pnpm build`, then open `/?map3d=1` and choose Play. Without the query, the same build uses the painted selector. Normal web and store builds compile the 3D scene out; the prototype sky is emitted as `/map-review/sky-alpine-a.png` only for the review build. This makes the 3D map testable in a phone browser without replacing the live selector before its art and device gates pass.

A silent 852×393 headless Chromium preview run produced the [phone-size map frame](phone.png) and [machine report](report.json). Menu → Play mounted one live 3D canvas, selected C1, fetched the sky at HTTP 200 and logged zero page errors. A second page with no `map3d` query opened the painted map and created no 3D host. The [played skyline comparison](../next-forest-skyline/README.md) separately verifies 12/12 tower taps and the full orbit in the development renderer. The production-style smoke establishes packaging and entry, not physical touch accuracy or frame pacing.

`src/store-build.test.ts` now builds normal web, store and explicit map-review variants: all 16 tests pass, including presence of the C-island scene and sky only in the review variant. The review build passed the normal 640 KB player JS budget at 626.1 KB; its separate 24.9 KB gzipped scene chunk is counted as review-only and loads on map entry. The 1.85 MB sky file is likewise absent from normal and store bundles. `pnpm typecheck` and `pnpm lint` passed. The user still needs to judge the moving map against the selected image on a real landscape phone before it can replace the painted selector.
