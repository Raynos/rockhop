# C-island open-water patch and repeated glints

The [selected island reference](../orbit-round4/selected-reference.jpg) carries one continuous blue-green sea around the cliffs. In the playable C map, the [before oblique view](before/three-quarter.png) showed a broad navy patch beside the island, with repeated straight glints running through it. Flattening the water mesh in the [earlier probe](../water-plane-probe/README.md) saved triangles but did not remove either artifact. The cause was in the **fragment shader**: open water reached a near-black `deep` color just outside a narrow shoreline band, and a high-power sine term repeated a straight highlight across the whole plane.

This candidate keeps the animated surface geometry, shoreline foam, horizon fade, island route and 12 tower meshes. It lightens and broadens the open-water transition and removes that periodic sine highlight. The existing noise ripples remain. Compare the silent **played** [before orbit](before/played-orbit.mp4) with the [after orbit](after/played-orbit.mp4), then the [front](before/front.png)/[after front](after/front.png), [oblique](before/three-quarter.png)/[after oblique](after/three-quarter.png), and [reverse](before/reverse.png)/[after reverse](after/reverse.png) frames. The after orbit reads as one teal sea at phone size and the rigid bright lines are quieter. It is visibly closer to the reference; the water is still procedural and needs physical-phone art judgment.

Both clips come from Menu → Play in headless WebKit at **852×393 CSS pixels, DPR 2**. Input drags the actual camera through a full orbit, then touch-taps every tower. [Before](before/report.json) and [after](after/report.json) reports each record **12/12 correct stage selections, zero page errors, 256 front/oblique draw calls and 412,634 triangles**. No tower or route code changed. The recorded WebKit front/oblique/reverse frame medians were 16.6–16.7 ms before and 16.4–16.7 ms after; recording p95 varied by a few milliseconds and is not a device performance claim. The MP4 files have no audio stream.

For timing without video encoding, [baseline](before-metal-no-video/measurements.json) and [candidate](after-metal-no-video/measurements.json) runs used headless Chromium with the verified `ANGLE Metal Renderer: Apple M5 Max` backend at the same 852×393 viewport and DPR 2. Both report 60 fps and 8.3 ms median at front, oblique and reverse. Oblique p95 is **10.0 ms both before and after**; reverse is 9.3 ms before and 9.1 ms after. Geometry and draw calls match, and each run selects the same 12 stage IDs with zero console/page errors. This verifies no measurable host-Metal pacing cost in this bounded run; it does not substitute for landscape iPhone thermal, touch or art review.
