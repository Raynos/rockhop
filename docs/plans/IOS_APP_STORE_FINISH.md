# iOS App Store finish and 3D world map remaster

**Status:** active, audited 2026-09-27 against `fa45298` plus the menu fixes in this round. This is the iPhone finish plan for [STORE_RELEASE.md](STORE_RELEASE.md). The game is playable and its native shell runs; it is not yet a finished App Store submission. The user has required a genuinely 3D, rotatable level map, a visible menu hero, and centered menu controls. The 3D map is required before the final iOS release. The first procedural map's visuals were rejected; its interaction scaffold is archived, and five new visual directions are [ready for selection](../../assets/design/worldmap-3d/mockups/README.md).

**Definition of done:** a stranger can install the signed TestFlight build on an iPhone, understand the first run, clear and restart real ROCKHOP courses, navigate the 12 main levels on the 3D map, and return to a polished menu. The same release archive has truthful listing and rights answers, working public support/privacy URLs, production screenshots from the player UI, and passes the release gates below. The user judges played clips and the actual phone build before submission; App Store approval closes the release.

The existing painted map and DOM diamond/plate markers are not the target.

- [x] Generate [five visual directions](../../assets/design/worldmap-3d/mockups/README.md), each as a nine-angle 3×3 concept board. The functional low-poly prototype proved rotation and selection but failed the user's graphical bar, so it is archived as interaction scaffolding only. Generated angles are visual studies, not a geometrically exact orbit of one mesh.
- [x] Generate nine one-view ideas for a 3D level-start object. The user selected the [roadside rally-flag tower, 09](../../assets/design/worldmap-3d/mockups/level-starts/board-3x3.jpg). Circular arenas/pads are rejected as level targets.
- [ ] The user chooses one map visual direction. Write `assets/design/worldmap-3d/SPEC.md` against that look and the chosen flag tower, then deliver a played full rotation clip from a measured phone-sized implementation.
- [ ] Use real 3D terrain/zone meshes, water, road, landmarks and atmospheric separation. The road remains legible through all four biomes at overview and close zoom. Avoid a flat plane textured with the old painting.
- [ ] Model exactly 12 grounded, clickable rally-flag towers beside the road, three per biome. Selection, progress, lock state and the level name attach to each tower. The 3D model and camera movement must reveal their depth; touch hit targets remain large even if the rendered prop is compact. No circular arenas or pads.
- [ ] Orbit/rotate, pan and zoom with touch, mouse, and keyboard/gamepad; a tap selects without also rotating. Provide a clear “return to route” control and focus path. - [ ] Gate performance on the actual iPhone: no sustained frame-rate regression from the current map, no terrain/texture memory spike that causes a WKWebView reload, and stable gesture handling during a full route sweep. Record played clips, not posed renders.
